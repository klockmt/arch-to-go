# arch-to-go Rust Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bash installer with a Rust workspace that installs a portable UEFI Arch system onto a USB disk from a TOML config or prompts.

**Architecture:** `core` builds a pure `Vec<Step>` from a validated `Config`; an executor runs it through a `Runner` trait (`DryRunner`, `MockRunner`, `RealRunner`). `cli` wires args, prompts and confirmation. Host tools (`sgdisk`, `mkfs.*`, `pacstrap`, `genfstab`, `arch-chroot`) do the real work.

**Tech Stack:** Rust (cargo 1.99), `serde` + `toml`, `clap`, `thiserror`, `rpassword`. Plain `assert_eq!` tests, no snapshot crate.

**Spec:** `docs/superpowers/specs/2026-11-02-rust-core-design.md`

## Global Constraints

- Branch `beta` only; merge to `main` only after user validation.
- UEFI x86_64 only; Limine installed on the removable path `EFI/BOOT/BOOTX64.EFI`; never write host NVRAM.
- No LUKS in v1. Filesystems: btrfs, ext4, xfs. Default btrfs subvolumes `@ @home @log @pkg`, mount opts `noatime,ssd,discard=async` (nodatacow only if the config asks).
- Safety invariants: whole USB disk only; refuse any host-backing disk; refuse mounted partitions; user types the exact device path; unmount `/mnt` on exit (lazy fallback); fail closed if lsblk/findmnt fail.
- Secrets (passwords, `.env` values) never appear in plans, dry-run output, logs, tests, docs or commits. Passwords reach `chpasswd` via stdin only.
- pacstrap uses the repo's own `pacman.conf` (host has CachyOS repos that must not leak into the target).
- Every mutating command honors `--dry-run` / `DRY_RUN=1`.
- Commits: `type(scope): summary`, small, English, no AI mention or trailers. Every bug gets a regression test with its fix.
- Real-device runs read `$ARCH_TEST_DEVICE`, `$ARCH_SUDO_PASSWORD`, `$ARCH_USER_NAME` from `.env`; never hardcode them.

## Review Focus

1. Disk names ending in a digit (`/dev/nvme0n1`, `/dev/mmcblk0`) must get the `p` partition suffix (Task 5).
2. Hostname, username, locale, timezone, keymap and package names are validated by strict allow-lists, and chroot commands use argv vectors, never `sh -c` strings built from config (Task 2, 6).
3. Passwords containing `:`, quotes, `$` or spaces work; empty or newline-containing passwords are rejected; the password never shows in dry-run output (Task 3, 6).
4. Config with an unknown key, empty kernel list, duplicate package or unsupported combination fails before any step runs (Task 2).
5. Ctrl-C or a failing step must leave `/mnt` unmounted (Task 3, 9).

**Interfaces:**

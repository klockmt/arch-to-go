# arch-to-go TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an archinstall-style terminal UI (`arch-to-go tui`) that edits the shared `Config` and drives the CLI as a subprocess.

**Architecture:** `crates/tui` holds a pure app state machine (`App::handle_key -> Effect`), a pure `draw` function, a child-process driver and a thin terminal loop. The CLI gains a `tui` subcommand. The TUI never touches a disk: every safety rule stays in `arch-to-go install`.

**Tech Stack:** Rust, `ratatui` (crossterm backend via `ratatui::crossterm`), `tempfile`, existing `arch-to-go-core`.

**Spec:** `docs/superpowers/specs/2026-11-02-tui-design.md`

## Global Constraints

- Work on branch `beta`; merge to `main` only after the user validates (never push or merge without asking).
- The TUI never mounts, partitions or writes a disk; no safety logic is duplicated (USB-only, host-disk refusal, exact typed path, recheck before the wipe and unmount all stay in the CLI).
- Starts as any user; Install needs root; without root it offers Save and shows the `sudo arch-to-go install ... --config ...` command. No privilege escalation code.
- Install enabled only when `Config::validate` passes, a disk is picked and a password is set. The TUI holds no copy of the validation rules.
- Password: held as `Secret`, never written to a file, the log, argv or the saved config; reaches the child only as `ARCH_ADMIN_PASSWORD` in its environment.
- Child binary is `std::env::current_exe()` (tests pass a stub path). Temp config lives in a private temp directory (mode 0700), deleted afterwards.
- Progress: a child line starting `==> ` is a step; every line goes to the log; a trailing partial line (the CLI's prompt) is flushed at EOF.
- Abort: Ctrl-C arrives as a key event (raw mode); the TUI runs `kill -INT <pid>` and waits for the child to exit.
- Minimum terminal size 80x24: below it, draw a "terminal too small" message instead.
- Out of scope: package search, mouse, themes, localization, in-process install, escalating to root.
- Commits: `type(scope): summary`, small, English, no AI mention or trailers. Every bug gets a regression test, committed with or before the fix. Run `scripts/check-repo` before each commit and gate the commit on its exit status.
- Personal data (user name, home paths, password) never appears in tracked files, tests or commits. Fake names in tests are fine; build home-like paths at run time (the repo scan rejects literal home paths).

## Review Focus

1. A password containing quotes, `:`, `$` or unicode is never drawn (masked) and never appears in the saved TOML or the log (Tasks 1, 4, 7).
2. A terminal of 0x0, 1x1 or 79x23 must not panic `draw` (Task 7).
3. The child cannot start (missing binary) or dies mid-run: the Done screen shows the failure and the temp directory is removed (Tasks 6, 8).
4. Saving to an unwritable path or loading invalid TOML shows a message and leaves the config unchanged (Tasks 5, 8).
5. No USB disk present, or a typed confirmation with a trailing space or another device's name: Install stays disabled / confirmation refused (Tasks 3, 5).
6. Unicode in text fields (multi-byte characters, backspace over them) does not panic (Task 4).

### Task 5: Review, Confirm, Run and Done flow

**Files:**
- Modify: `crates/tui/src/app.rs`; Test: same place

**Interfaces:**
- Consumes: `Effect`, `ChildEvent`, `Line`/`classify`.
- Produces: transitions and effects:
  - Menu Enter on Review (config valid and device set) returns `Effect::Review`; the caller then fills `app.review` and the app shows `Screen::Review` (scroll with Up/Down/PageUp/PageDown; Esc back). Review with an invalid config sets `app.message` and stays on the Menu.
  - Menu Enter on Install, not root: no effect on the screen; `app.message` becomes `root needed: save the config and run sudo arch-to-go install <device> --config <path>` (the `<path>` is the file last saved, or a placeholder `config.toml` when none). The menu's Save entry asks for a path in a text field; Enter returns `Effect::Save(path)`. Load works the same and returns `Effect::Load(path)`.
  - Menu Enter on Install, root and `can_install`: goes to `Screen::Confirm`. If `can_install` is false it sets `app.message` and stays.
  - Confirm: the user types the device path; Enter with an exact match (no trimming) returns `Effect::Install` and goes to `Screen::Run`; any other text shows `app.message` and stays; Esc goes back to the Menu.
  - `on_event(ChildEvent::Line(l))` appends to `app.log` and, for `Line::Step(s)`, sets `app.step`; `on_event(ChildEvent::Exited(code))` sets `app.exit_code` and moves to `Screen::Done`.
  - Run: Ctrl-C returns `Effect::Abort` once and sets `app.message` to `aborting, waiting for cleanup`; further keys do nothing until `Exited`.
  - Done: Enter or `q` returns to the Menu (or `Effect::Quit` with `q`); the log stays scrollable.
  - `App::apply_loaded(&mut self, cfg: Config)` replaces the config (device and password are kept); `App::set_review(&mut self, lines: Vec<String>)` sets `app.review` and switches to `Screen::Review`.

### Task 8: Runtime and terminal loop

**Files:**
- Create: `crates/tui/src/runtime.rs`; Modify: `crates/tui/src/lib.rs`; Test: `crates/tui/tests/runtime.rs`

**Interfaces:**
- Consumes: `App`, `Effect`, `Child`, `install_args`, `draw`, `Config::to_toml`/`from_toml`.
- Produces:
  - `pub struct Runtime { pub exe: std::path::PathBuf, /* temp dir, child */ }`
  - `Runtime::new(exe: PathBuf) -> Runtime`
  - `Runtime::perform(&mut self, effect: Effect, app: &mut App)`: `Review` writes the config to `<tempdir>/config.toml` (dir mode 0700) and runs `install DEV --config F --dry-run` with `ARCH_ADMIN_PASSWORD` set to the real password if present, collecting stdout until exit, then `app.set_review(lines)`; `Install` writes the config, spawns the real install with `ARCH_ADMIN_PASSWORD`, sends the device path plus newline to its stdin, and keeps the `Child` so `poll` can forward events; `Abort` calls `interrupt`; `Save(path)` writes `Config::to_toml` and sets `app.message` on success or failure; `Load(path)` reads and parses, calling `app.apply_loaded` or setting `app.message` and leaving the config unchanged; `Quit` does nothing here.
  - `Runtime::poll(&mut self, app: &mut App)`: drains the child's `rx` into `app.on_event`; on `Exited`, drops the child and removes the temp directory. A failed spawn calls `app.on_event(ChildEvent::Line(<error>))` then `Exited(127)`.
  - `pub fn run(initial: Option<Config>) -> Result<(), String>`: refuses when stdin or stdout is not a terminal (`arch-to-go tui needs a terminal`), lists USB disks, determines root as the CLI does (owner of `/proc/self` is 0), enters raw mode and the alternate screen, installs a panic hook that restores the terminal, and loops `draw`, `poll`, key read with a 100 ms timeout, `handle_key`, `perform`; always restores the terminal on exit.
